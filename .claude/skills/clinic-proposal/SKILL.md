# クリニック向け提案書づくり

サービス案を、**忙しい院長が10分で判断できる提案資料**に整える。院長が知りたいのは技術ではなく「売上・手間・リスクがどう変わるか」なので、その順で書く。

## 手順

1. **前提を集める**（不足していれば最初にまとめて質問する。答えがなければ仮置きして【仮定】と明記する）
   - 提案先：クリニックの規模（医師数・スタッフ数・月の来院数）、主な施術、立地、集客チャネル
   - 提案するサービス：何をするか、誰が使うか（患者 / スタッフ / 医師）、料金案
   - 提案の目的：試験導入の獲得か、本契約か、共同開発か
2. **課題を院長の言葉で書く**：「スタッフの電話対応が多い」「術後の不安からキャンセルや他院流出が起きる」など、現場で起きている具体的な出来事にする
3. **[references/template.md](references/template.md) の構成に沿って本文を書く**
4. **効果試算を出す**：計算式と前提をすべて見せる（下記「数字のルール」）
5. **法令・リスクの章を必ず入れる**：医療広告ガイドライン、個人情報（要配慮個人情報）、医師法（AIは診断しない・最終判断は医師）、オンライン診療の指針など、サービスに関係するものだけを挙げ、どう配慮しているかを書く
6. **出力する**：まずMarkdownで全文を出す。ユーザーがスライド・PDF・Word・ドキュメントを希望した場合は、その形式を作るスキルやツールで仕上げる（スライドなら1スライド1メッセージ、10〜12枚を目安にする）

## 数字のルール

- 効果は**「保守的 / 標準」の2パターン**で出し、楽観シナリオは出さない
- 例：`問い合わせ電話 月200件 × 削減率30% × 1件5分 = 月50時間 ≒ 人件費 約8万円（時給1,600円で計算）`
- クリニックの実数が分からない数字は【仮定】と書き、差し替えてもらう前提にする
- 「売上◯倍」「必ず増える」のような保証表現は使わない

## 文章のルール

- 専門用語（LLM、API、SaaSなど）は使わないか、使うなら一言で説明する
- 1ページ目（エグゼクティブサマリー）だけで、提案の内容・効果・費用・次にやることが分かるようにする
- 患者向けの表現例を載せる場合は、`medical-ad-check` スキルの基準で問題がないか確認する
- 提案先の他院・競合を悪く書かない
