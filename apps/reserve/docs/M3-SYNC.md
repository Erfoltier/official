# LANE RESERVE → M3 デジカル 受付画面への予約の写し（RPA）

院長の決定（2026-11-21）：

- 方式：院内のパソコン（デジカルにログインできるもの）でブラウザを自動操作（RPA）し、デジカルの受付画面に1件ずつ入れる。デジカルの公開 API・エージェントV2 は使わない（エージェントV2 はオン資端末・WebORCA など院内機器の連携用）
- 範囲：**今日以降の新規予約**を写す。そのあとの**変更・取消も追いかける**。予約不可（ブロック）の枠は写さない
- 範囲（11/21 追加）：**今デジカルにある予約（スタッフの手入力）には触らない**。写し始めた時刻より後に LANE RESERVE で作られた予約と、その変更・取消だけを写す（`createdAt` が開始時刻以降の予約）
- 例外（11/21）：写し始める前からある予約（スタッフの手入力）でも、**LANE RESERVE の予約カレンダーで取り消されたら、デジカルの予約も取り消してよい**。デジカル側は 患者番号＝`m3ChartNo`・日付・受付メモ先頭の開始時刻（4桁）で探し、ちょうど1件に決まらなければ取り消さず「要確認」。前からある予約の時刻などの変更は写さない（デジカルにどう入っているか LANE RESERVE からは分からないため、これまでどおりスタッフが両方を直す）
- 予約メモの要約：**Claude が写すたびに要約**する（決まった手順のプログラムだけでは要約しない）。そのため写しは Claude Code のセッションから動かす
- 作業場所：院内パソコンの `C:\claude code\lane-m3`（クラウドのセッションからパソコンのフォルダを使う機能は、このアカウントではまだ使えなかったため、院内パソコンの Claude Code で進める）
- ブランチ：`claude/m3-reserve-sync`（本番の反映は従来どおり `sudo /srv/reserve/bin/release <コミット> claude` で、反映前に開発ブランチ `claude/admiring-wozniak-kikcrr` と合わせる）

## 守ること

- 患者情報・ログイン情報・鍵を、会話・ログ・コミットに出さない。デジカルのログインは院内パソコンのブラウザに任せ、プログラムやリポジトリに書かない
- 間違った患者に入れない：LANE RESERVE の患者の `m3ChartNo`（カルテ番号）で照合する。カルテ番号のない方・同姓同名の候補が複数ある方は入れずに「要確認」に回す
- 二重に入れない：写した予約は LANE RESERVE 側に「写し済み（デジカル側の識別・写した版）」を残し、同じ版を二度入れない
- 最初は1日分を院長が見ている前で入れ、デジカルの画面と照合してから広げる。実患者の登録の前には院長の明示の了承を取る
- 本番データを変える前は `sudo /srv/reserve/bin/backup <理由>`

## LANE RESERVE 側の口（2026-11-21 作成、未反映）

連携トークン（`Authorization: Bearer …`）で使う。中身は `Store::m3SyncQueue`／`recordM3Sync`。

- `POST /api/v1/integration/m3-sync/start`：写し始める。始めた時刻（`startAt`）は一度決めたら変えない。この時刻より後に作られた予約を写す
- `GET /api/v1/integration/m3-sync?from=YYYY-MM-DD`（省略で今日）：`{ startAt, items, review }`
  - `items[].action`：`create`（始めた後に作られ、まだ写していない）／`update`（写した後に患者・日時・レーン・メニュー・メモが変わった）／`cancel`（写した予約の取消、または始める前からある予約が始めた後に取り消された＝`preexisting: true`）／`restore`（取消を写した後に予約へ戻した）
  - `items[].reservation`：`id`・`fingerprint`・`date`・`time`（受付メモ先頭の4桁）・`startAt`・`endAt`・`minutes`・`lane`・`menus`（名前・略称）・`memo`・`preexisting` など。`patient`：`m3ChartNo`・氏名・カナ・性別・生年月日・電話・住所。`previous`：前に記録した結果（デジカルに入れた番号・日時・受付メモの1行目）
  - `review`：要確認にしたまま中身が変わっていない予約（スタッフが確かめる）。予約が直されたら `items` に戻る
  - 予約不可の枠（メニューか患者の名前に「予約不可」）は出さない。無断キャンセルは写さない（当日スタッフがデジカルで扱う）
- `POST /api/v1/integration/m3-sync/reservations/{id}`：`{ result: synced|cancelled|review, fingerprint, reason?, digikar?: { patientNo, date, time, memoLine? } }`。`fingerprint` が今の予約と違えば 409（写している間に変わった → 一覧を読み直す）。要確認は理由が必須
- 写した記録は DB の `m3sync`（予約ごと、直近10回の履歴つき）。監査には「外部連携」で残る

## 作るもの（案）

1. LANE RESERVE 側（PHP）：連携トークンで読める「デジカルへ写す予約の一覧」
   - 今日以降・予約不可以外・新規作成と、その後の変更・取消
   - 予約ごとに写した状態（未・写し済み〈版〉・要確認〈理由〉）を記録する受け口
2. 院内パソコン側（RPA、Playwright）：一覧を読み、デジカルの受付画面で登録・変更・取消し、結果を LANE RESERVE に返す
   - デジカルの画面の入力欄・ボタンは、院内パソコンで実際の画面を見て決める（推測で作らない）
   - 1件ごとに画面を読み直して確かめ、確かめられなければ止めて「要確認」にする

## デジカルの画面で確かめたこと（2026-11-21、院内パソコンの Chrome、読むだけ・保存なし）

- デジカルは端末の証明書が必要。Claude アプリ内のブラウザ（証明書なし）では 400 で開けない。院内パソコンの Chrome（証明書あり・ログイン済み）なら開ける。RPA もこの Chrome（またはそのプロファイル）を使う必要がある
- 受付一覧：`https://digikar.jp/reception/YYYYMMDD`。列は 番号・予約・時間・ステータス・患者番号・患者氏名・年齢・保険・診療科・医師・前回受付日・患者メモ・受付メモ・会計。先の日付も開ける（11/24 は 0件）
- 一覧の右上のボタン：日計表・帳票・受付編集履歴・受付更新（予約を入れるボタンはここにはない）
- 予約の入口：上部の「検索」（虫めがね）→「患者検索」（患者番号・フリガナ・名前・生年月日で検索、各行に 表示・受付・**予約**、下に「一括予約」）。練習用の患者（レンシュウ …）がいる
- 「予約登録」の画面：左に患者の予約一覧（＋で追加）、右に 予約日（yyyy/mm/dd）・患者・医師（選択式の入力欄）・診療科（皮膚科）・保険・公費1〜3・**予約時間（開始時刻だけ。終了・長さの欄はない）**・受付メモ・予約票／受付メモを備考に印字・キャンセル／登録
- レーン・メニュー・所要時間を入れる欄はないため、受付メモに入れる
- **今の水曜・祝日の予約はスタッフが手でデジカルに入れている**（11/23・11/25・12/2・12/9・12/16 で確認。医師はすべて石田 卓、時刻なしの「購入」だけの行もある）。写しを始めると同じ予約が二重になるので、同じ患者・同じ日の予約がすでにあれば新しく入れず「要確認」にする

## 予約の変更・取消の画面（2026-11-21 確認、保存なし）

- 受付一覧の各行の右端のボタン（カレンダーの印）→ その患者の「予約登録」画面。左の「予約一覧」に予約（例 `2026/12/16(水) 10:00`）が並び、それぞれに **編集・削除・カルテ表示** のボタン
- 「編集」→ 右側が「予約編集」になり、予約日・医師・診療科・保険・公費・予約時間・受付メモを直して「更新」
- 取消のしかたは2通り：①ステータスのメニュー（予約済・受付中・診察待・診察中・検査中・処置中・会計待・会計済・再計待・不在・**取消**）で「取消」にする（一覧からは消え、受付編集履歴に残る。下の「練習用の患者で試した結果」）②予約一覧の「削除」（行が消える）。**院長の決定（11/21）：①ステータスを「取消」にする**（削除はしない）
- 受付一覧の行では、保険・診療科・医師・受付メモをその場で直す鉛筆のボタンも出る（RPA は使わず、予約編集の画面で直す）
- 今からある患者の予約登録では、保険はその患者の保険が初めから入っている

## 練習用の患者で試した結果（2026-11-21 16:29〜16:30、院長の了承・立ち会いのもと）

患者番号2（レンシュウ ハナコ）で、11/24（受付0件の日）10:00 に登録 → 10:30 に変更 → 取消。受付メモは「1000テスト　LANE RESERVE写しの練習」→「1030…」。

- 患者検索に番号を入れると**部分一致**（「2」で3万件以上）。患者番号がちょうど同じ行を選ぶこと（先頭に出るが、必ず番号を照合する）
- 予約日・予約時間は、文字を流し込んでも受け付けない（画面の部品が値を持つ）。予約日の右のカレンダーのボタン →「予約状況カレンダー」（月の小さなカレンダー＋週の30分ごとの枠、日ごとの件数、医師の絞り込み）で日と時刻の枠を押すと、予約日と予約時間が入る。予約時間の欄を押すと30分刻みの一覧も出る。30分刻みでない時刻（10:20 など）は、予約時間の欄を押して Ctrl+A → キーで `10:20` と打ち、**Tab で欄を離れる**と入る（11/21 16:35 に患者番号2で 11/24 10:20 を登録・取消して確認）。Esc は画面ごと閉じるので使わない。手順：カレンダーのボタン → 日と近い枠を押す（予約日が入る）→ 予約時間を打ち直す
- 受付メモは文字を流し込めた
- Esc を押すと予約登録の画面ごと閉じる（保存されない）
- 「登録」「更新」の後、左下に「患者番号 2 を 2026/11/24 (火) に予約しました」と出る。変更しても行は増えない（同じ予約が直る）
- ステータスを「取消」にすると、確かめの画面は出ず、**受付一覧からも患者の予約一覧からも消える**（「行は残る」は誤り）。記録は「受付編集履歴」に残る（予約時刻・ステータス 取消・作成日時・最終編集日時・最終編集者＝デジカルにログインしているスタッフ）
- RPA の操作はログインしているスタッフの名前で記録される。LANE RESERVE からの写しだと分かるよう、受付メモの先頭の決まりと LANE RESERVE 側の記録（`m3sync`）で追う

## 完全初診の方（院長の指示 2026-11-21）

- LANE RESERVE の情報からデジカルで新規患者登録し、その患者で予約を入れる。付いた患者番号は LANE RESERVE の `m3ChartNo` に書き戻す（既存の `POST /api/v1/integration/patients/{id}/m3-chart-no`）
- デジカルの「患者情報登録」（患者検索 → 新規患者登録）：患者番号（自動で次の番号が入る）・漢字氏名・カナ氏名（全角カナ）・性別（**初期値が男性**）・生年月日（年・月・日）が必須。住所（郵便番号・都道府県・市区町村・番地・建物）・電話番号1／2・施設は任意。ボタンは キャンセル／登録／登録して受付（予約なので「登録」を使う）
- 二重登録を防ぐ：登録の前にデジカルの患者検索でカナ氏名・生年月日（・電話）を調べ、候補が1人でもいれば登録せず「要確認」。LANE RESERVE に氏名・カナ・性別・生年月日のどれかがなければ登録せず「要確認」（性別を初期値のまま入れない）

## 受付メモの書き方（院長の指示 2026-11-21。今のスタッフの書き方に合わせる）

- 先頭に開始時刻を半角4桁（例 `1000`）、続けて空けずに施術・初診／再診（例 `1000シミ初診`、`1040レーザー脱毛再診　髭`）。終了時刻は書かない
- 補足は全角スペースで区切って続ける
- 略し方の例：炭酸ガスフラクショナル→フラ（部分フラ）、トラネピンク、TAピンク、フィル、ジュベ（ジュベルック）、ボト、イソ、サリ、色素（色素レーザー）
- 回数もの：`トラネピンク3/5`（5回コースの3回目）
- モニターで撮影から始まる人：`モニター　ネオボ`・`撮影`
- 麻酔：スタンプ注射・ピンク・フィル・トラネなどは麻酔クリームが標準なので書かない。注射でする人だけ `局麻で`・`麻酔注射で`、なしは `麻酔なしで`
- 同伴：予約メモに同伴とあれば `〇〇さん同伴`
- 看護師の指名：`斎川さんで`
- 相談のみ・支払い済などの大事なことは、予約メモから要約して書く
- LANE RESERVE のメニュー → デジカルの略し方の対応表が必要（未作成）

## 決まっていないこと（院内パソコンで画面を見てから）

- LANE RESERVE のレーン・メニューを、デジカルのどの項目に対応させるか
- 動かす間隔（数分ごと／手動で1回ずつ）
