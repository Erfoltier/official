# LANE RESERVE → M3 デジカル 受付画面への予約の写し（RPA）

院長の決定（2026-11-21）：

- 方式：院内のパソコン（デジカルにログインできるもの）でブラウザを自動操作（RPA）し、デジカルの受付画面に1件ずつ入れる。デジカルの公開 API・エージェントV2 は使わない（エージェントV2 はオン資端末・WebORCA など院内機器の連携用）
- 範囲：**今日以降の新規予約**を写す。そのあとの**変更・取消も追いかける**。予約不可（ブロック）の枠は写さない
- 範囲（11/21 追加）：**今デジカルにある予約（スタッフの手入力）には触らない**。写し始めた時刻より後に LANE RESERVE で作られた予約と、その変更・取消だけを写す（`createdAt` が開始時刻以降の予約）
- 例外（11/21）：写し始める前からある予約（スタッフの手入力）でも、**LANE RESERVE の予約カレンダーで取り消されたら、デジカルの予約も取り消してよい**。デジカル側は 患者番号＝`m3ChartNo`・日付・受付メモ先頭の開始時刻（4桁）で探し、ちょうど1件に決まらなければ取り消さず「要確認」。前からある予約の時刻などの変更は写さない（デジカルにどう入っているか LANE RESERVE からは分からないため、これまでどおりスタッフが両方を直す）
- 予約メモの要約：**Claude が写すたびに要約**する（決まった手順のプログラムだけでは要約しない）
- 動かし方（11/21 変更）：**Chrome の拡張機能**にする。LANE RESERVE の設定からダウンロードして各パソコンの Chrome に入れ、ON にする。その Chrome で LANE RESERVE とデジカルにログインしていれば、どれか1台が写す（同時に写すのは1台だけ＝LANE RESERVE 側の札）。パソコンごとの鍵は使わず、LANE RESERVE のスタッフのログインで読む。24時間起動のパソコンはないが、来院までに入っていればよいので、診療時間中にどれか1台が起動していれば足りる
- 要約の場所（11/21）：**LANE RESERVE のサーバーで Claude（Anthropic の API）に要約させ**、受付メモの1行を作って拡張機能に渡す。予約メモの内容はサーバーから Anthropic に送られる（院長の了承済み）。Claude の利用キーは院長が LANE RESERVE の設定に1回だけ入れる
- 完全クラウド（AWS だけで動かす）は今はしない：デジカルの端末証明書・ログインを院外のサーバーに置くことになり、M3 の約束事と院の個人情報の扱いを先に確かめる必要があるため
- 作業場所：院内パソコンの `C:\claude code\lane-m3`（クラウドのセッションからパソコンのフォルダを使う機能は、このアカウントではまだ使えなかったため、院内パソコンの Claude Code で進める）
- ブランチ：`claude/m3-reserve-sync`（本番の反映は従来どおり `sudo /srv/reserve/bin/release <コミット> claude` で、反映前に開発ブランチ `claude/admiring-wozniak-kikcrr` と合わせる）

## 守ること

- 患者情報・ログイン情報・鍵を、会話・ログ・コミットに出さない。デジカルのログインは院内パソコンのブラウザに任せ、プログラムやリポジトリに書かない
- 間違った患者に入れない：LANE RESERVE の患者の `m3ChartNo`（カルテ番号）で照合する。カルテ番号のない方・同姓同名の候補が複数ある方は入れずに「要確認」に回す
- 二重に入れない：写した予約は LANE RESERVE 側に「写し済み（デジカル側の識別・写した版）」を残し、同じ版を二度入れない
- 最初は1日分を院長が見ている前で入れ、デジカルの画面と照合してから広げる。実患者の登録の前には院長の明示の了承を取る
- 本番データを変える前は `sudo /srv/reserve/bin/backup <理由>`

## LANE RESERVE 側の口（2026-11-21 作成、未反映）

連携トークン（`Authorization: Bearer …`）で使う。中身は `Store::m3SyncQueue`／`recordM3Sync`。

- `POST /api/v1/integration/m3-sync/start`：写し始める。始めた時刻（`startAt`）は一度決めたら変えない。この時刻より後に作られた予約を写す
- `GET /api/v1/integration/m3-sync?from=YYYY-MM-DD`（省略で今日）：`{ startAt, items, review }`
  - `items[].action`：`create`（始めた後に作られ、まだ写していない）／`update`（写した後に患者・日時・レーン・メニュー・メモが変わった）／`cancel`（写した予約の取消、または始める前からある予約が始めた後に取り消された＝`preexisting: true`）／`restore`（取消を写した後に予約へ戻した）
  - `items[].reservation`：`id`・`fingerprint`・`date`・`time`（受付メモ先頭の4桁）・`startAt`・`endAt`・`minutes`・`lane`・`menus`（名前・略称）・`memo`・`preexisting` など。`patient`：`m3ChartNo`・氏名・カナ・性別・生年月日・電話・住所。`previous`：前に記録した結果（デジカルに入れた番号・日時・受付メモの1行目）
  - `review`：要確認にしたまま中身が変わっていない予約（スタッフが確かめる）。予約が直されたら `items` に戻る
  - 予約不可の枠（メニューか患者の名前に「予約不可」）は出さない。無断キャンセルは写さない（当日スタッフがデジカルで扱う）
- `POST /api/v1/integration/m3-sync/reservations/{id}`：`{ result: synced|cancelled|review, fingerprint, reason?, digikar?: { patientNo, date, time, memoLine? } }`。`fingerprint` が今の予約と違えば 409（写している間に変わった → 一覧を読み直す）。要確認は理由が必須
- 写した記録は DB の `m3sync`（予約ごと、直近10回の履歴つき）。監査には「外部連携」で残る

## 作るもの（案）

1. LANE RESERVE 側（PHP）：連携トークンで読める「デジカルへ写す予約の一覧」
   - 今日以降・予約不可以外・新規作成と、その後の変更・取消
   - 予約ごとに写した状態（未・写し済み〈版〉・要確認〈理由〉）を記録する受け口
2. 院内パソコン側（RPA、Playwright）：一覧を読み、デジカルの受付画面で登録・変更・取消し、結果を LANE RESERVE に返す
   - デジカルの画面の入力欄・ボタンは、院内パソコンで実際の画面を見て決める（推測で作らない）
   - 1件ごとに画面を読み直して確かめ、確かめられなければ止めて「要確認」にする

- 拡張機能 `extensions/m3-sync/`（設定 → 外部機器の連携 →「デジカルへの予約の写し」から zip でダウンロード。`scripts/zip-extension.mjs` が作る）

  - `digikar.js`：デジカルの画面の操作。ふつうのページのスクリプト（クリック・値の流し込み・Enter／Tab）で、11/21 に練習用の患者で登録（10:20）・取消ができることを確認済み。取消はステータスのメニューを開いて「取消」を Enter で選ぶ（クリックでは選ばれない）

    - 取消：その日の一覧で 患者番号・時刻（自分で写した予約は受付メモの先頭の4桁も）の行が1件 → ステータスを「取消」→ 一覧から消えたことを確かめる
    - 途中で止まったら保存せずにキャンセルで閉じ、要確認にして、その回はそれ以上続けない
  - `background.js`：2分ごと（ポップアップで ON にしたパソコンだけ）。札を取れたら一覧を読み、1回に5件まで。写し専用のデジカルのタブを裏で開く（ピン留め）

- 設定の画面「デジカルへの予約の写し」（院長だけ）：Claude の利用キー・試運転の患者番号・写し始め・今写しているパソコン・要確認の一覧・拡張機能のダウンロード
- **試運転**：患者番号を入れている間は、その患者の予約だけを写す（練習用の患者2など）。空にして保存すると本番になり、写し始めがその時刻に変わる（試運転の間に入った本物の予約は、スタッフが手で入れているので写さない。取消だけは写す）

## Claude の使いすぎの歯止め（院長 11/21、未反映）

- LANE RESERVE のサーバー側で、どのパソコン・どの版の拡張機能から呼ばれても効く（`M3Memo::reserveCall`・`addCost`）
  - 月の上限（既定 3,000円、設定で変えられる）：使ったトークンから円を見積もって足し（Opus 5.5 は 100万トークンあたり入力4ドル・出力20ドル、1ドル155円）、上限に達したら Claude を呼ばない。写しは要確認で止まる
  - 1,000円をまたぐごとに警告（設定の画面・拡張機能のポップアップ・監査記録）
  - くり返しの歯止め：同じ予約は1日5回まで、全体で1時間30回・1日200回まで。超えたら止める
  - 1回の呼び出しは出力 1,024 トークンまで、やり直しは1回・30秒で打ち切り
- 拡張機能：1回に5件まで、要確認が出たらその回は止める（もとから）。ポップアップに今月の見積もりと警告
- 見積もりは目安。実際の請求と強い上限は Anthropic の管理画面（月の上限額）で決める
