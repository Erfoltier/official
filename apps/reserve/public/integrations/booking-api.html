自動予約プログラムの接続マニュアル

ChatGPT などの自動予約プログラムが、LANE RESERVE（レーンリザーブ）に予約を入力・変更・取り消しし、カルテ・写真・問診票・同意書・見積・設定も扱うための設定と使い方です。院長・管理者と、プログラムを設定する人に向けています。

1. できること・できないこと

できること

  • レーン・メニュー・診療時間を調べる
  • 日付ごとの予約を見て、空いている時間を探す
  • 患者を探す。見つからなければ新しく登録する
  • 予約を入れる・日時やレーンを移す・メニューを足す／外す・予約メモや予約申請IDを直す
  • 予約を取り消す（削除）・無断キャンセルにする・取り消した予約を予約に戻す
  • 予約に付けたいメニューがないとき、メニューを新しく作る

スタッフの画面と同じ操作（10章）

  • カルテ（施術の記録）・日付ごとのメモ・患者の基本情報を見る・直す
  • 写真・ファイル、問診票、同意書、見積を見る・作る・直す
  • レーン・メニュー・状態・スキンケア・料金表・院の情報・リマインドなどの設定を見る・変える

できないこと（安全のため）

  • スタッフの登録・PIN・二要素認証・端末の登録、接続キーの発行
  • 控えからの復元、データの保存先の操作、バックアップの実行
  • 過去の時刻への予約（予約の入口から）、同じレーンで時間が重なる予約（二重予約）
  • Airリザーブで入れた予約の変更・取り消し（Air から15分ごとに取り込んでいるため、Air で変えてください）

プログラムがしたこと・見たものは、予約や患者の変更履歴、設定の「操作ログ」「閲覧の記録」に「自動予約（キーの名前）」として残ります。

2. 準備：接続キーを発行する（院長・管理者）

  1. LANE RESERVE を開き、設定 → 外部機器の連携 を開きます。
  2. 「自動予約プログラムの接続キー（ChatGPT など）」の欄で、キーの名前（例：ChatGPT 自動予約）を確かめて「接続キーを発行」を押します。
  3. bk_ で始まる接続キーが1回だけ表示されます。「コピー」を押して、すぐにプログラムの設定（次の章）に貼り付けてください。画面を閉じると二度と表示されません。
  4. 同じ欄に出ている入口のアドレス（https://reserve.ishidahihuka.jp/api/v1/integration/booking）も控えます。
接続キーは、院長と同じようにカルテ・患者情報・設定を見て変えられる大切な鍵です。チャットの本文・メール・紙に書かないでください。漏れたかもしれないときは、同じ欄の「このキーを無効化」を押してから、新しいキーを発行し直してください。無効にしたキーはすぐ使えなくなります。

プログラムごとに別のキーを発行すると、どのプログラムが入れた予約か履歴で見分けられ、1つだけ止めることもできます。

3. ChatGPT（GPT のアクション）に設定する

ChatGPT の「GPT を作成」で自動予約用の GPT を作る場合の手順です。ほかのプログラムでも、考え方は同じです（入口のアドレスに、接続キーを付けて送る）。

  1. ChatGPT で GPT を作成 → 構成 → 新しいアクションを作成する を開きます。
  2. 「認証」で API キー を選び、「API キー」に接続キーを貼り付け、「認証タイプ」は カスタム、「カスタムヘッダー名」に X-Booking-Token と入れて保存します。
  3. 「スキーマ」に、この下の「プログラムに貼るスキーマ」を全部コピーして貼り付けます。getOptions・getDay などの操作が並べば読み込めています。
  4. 「テスト」で ping を実行し、"ok": true が返ることを確かめます。
  5. GPT の「指示」に、たとえば次のように書いておくと、予約の取り違えを防げます。 
    ・予約を入れる前に、必ず getOptions でメニューとレーンを確かめ、getDay でその日の空きを確かめる。
・患者は ensurePatient で、氏名・フリガナと、生年月日か電話番号を必ず送って探す（なければ登録される）。
・予約を入れる・変える・取り消す前に、日時・メニュー・お名前を相手に読み上げて確認をもらう。
・変更と取り消しには、直前に読んだ予約の version を付ける。
・エラーが返ったら、message の内容をそのまま相手に伝え、勝手に別の時間に入れない。
LANE RESERVE は入口に Basic 認証（ブラウザで開くときの ID・パスワード）を掛けています。自動予約の入口（/api/v1/integration/booking/）だけは、接続キーで確かめるため Basic 認証なしで入れるようにしてあります。プログラムからつながらないときは、サーバー担当に確認してください。

4. 予約を入力する

プログラムは、次の順で操作します。スタッフが画面で予約を入れるときと同じ流れです。

  1. メニューとレーンを調べる（getOptions）。メニューの番号（id）と、所要時間（duration：fixed なら minutes 分、range なら min〜max 分）、レーンの番号が分かります。
  2. その日の予約を見て空きを探す（getDay、例：date=2026-10-21）。取り消し済み（status が cancelled・no_show）の予約は空きとして扱えます。診療日は水曜・祝日・特別診療日です。
  3. 患者を探す・登録する（ensurePatient）。氏名・フリガナと、生年月日か電話番号を送ります。
    • フリガナ＋生年月日、または氏名（かフリガナ）＋電話番号が合う人が1人いれば、その人が返ります（created: false）。
    • いなければ新しく登録され（created: true）、スタッフ画面の「要確認の患者」に出ます。スタッフは重複がないか確かめて印を外してください。
    • 同じ方が複数登録されているときはエラーになります。スタッフが患者をまとめて（統合して）からやり直してください。
  4. 予約を入れる（createReservation）。送る内容：
    項目意味例
    patientId手順3で返った患者の番号p-new-…
    laneIdレーンの番号l1
    menuIdsメニューの番号（1〜5個）["m3"]
    startAt / endAt開始・終了の日時（日本時間の +09:00 を付ける）2026-10-21T10:00:00+09:00
    memo（任意）予約メモ（受付で見えます）LINEでご相談、初めて
    requestId（任意）予約申請ID（R＋数字で始まる番号）。付けると、その方は LINE の問診票をすぐ書けますR2026101710000012AB34CD
    成功すると、予約の番号（id）と version: 1 が返り、カレンダーにすぐ出ます。前日18時のリマインドも、スタッフが入れた予約と同じように送られます。

5. 予約を変更する

  1. 変える予約を読みます（getReservation、または getDay の一覧から）。返ってきた version（数字）を控えます。
  2. updateReservation に、version と、変える項目だけを送ります。変えられるのは次のとおりです。
    項目変えること
    startAt・endAt日時（予約の移動。長さを変えるときは両方送る）
    laneIdレーン
    menuIdsメニュー（全部を送り直します。足すときは今の menuIds に足した並びを、外すときは除いた並びを送る。1〜5個）
    memo予約メモ（送った文に置き換わります。空 "" で消す）
    requestId予約申請ID（空 "" で外す）
    statusbooked（予約に戻す）・cancelled（キャンセル）・no_show（無断キャンセル）
    例：時刻を11時に移す 
    { "version": 1, "startAt": "2026-10-21T11:00:00+09:00", "endAt": "2026-10-21T11:30:00+09:00" }
  3. 成功すると、version が1つ増えた予約が返ります。時刻を変えると、送ったリマインドは送り直しの対象になります。

スタッフが画面で同じ予約を先に直していると、「他の端末で先に更新されました」（409）になります。もう一度読み直して、新しい version で送り直してください。

6. 予約を取り消す（消去）

  1. 予約を読んで version を控えます。
  2. cancelReservation に { "version": 1 } を送ります。
  3. 予約は「キャンセル」になり、カレンダーの「キャンセルを表示」で見えます。記録は完全には消えません（あとから誰がいつ取り消したか分かるように。スタッフが画面で取り消したときと同じです）。DELETE /reservations/{id} でも同じように取り消されます。
  4. 間違えて取り消したときは、updateReservation で { "version": （今の数字）, "status": "booked" } を送ると予約に戻ります（その時間がふさがっていれば戻せません）。

メニューを新しく作る

予約に付けたいメニューが getOptions にないときは、createMenu に名前と所要時間を送ると作れます。作ったメニューは設定 → メニュー に並び、スタッフが色・料金・略称などを直せます。 

{ "name": "ハイドラフェイシャル（体験）", "duration": { "kind": "fixed", "minutes": 30 }, "defaultMinutes": 30 }
所要時間は5分単位です。同じ名前のメニューを何度も作らないよう、先に getOptions で探してください。

7. うまくいかないとき（エラーの意味）

エラーのときは、message に日本語の理由が入ります。プログラムにはそのまま相手に伝えさせてください。

番号意味どうする
401接続キーがない・違う・無効にされた設定 → 外部機器の連携 でキーを確かめ、必要なら発行し直す
400入力が足りない・形が違う、過去の時刻、Air の予約、取り消し済み などmessage を読んで直す。「入力内容が正しくありません」は、項目名や日時の形（+09:00 付き）を確かめる
404予約が見つからない予約の番号を確かめる
409その時間はふさがっている／先にほかで更新された／同じ患者が複数いる空きを探し直す・読み直して新しい version で送る・スタッフに患者の統合を頼む

8. 運用の注意

  • Airリザーブとの二重予約に注意してください。プログラムが LANE RESERVE に入れた予約は Air には入りません。Air のネット予約を受け付けている時間帯には、Air 側でも枠を押さえるか、プログラムで入れる枠を決めておいてください。
  • Air で入れた予約は、15分ごとに LANE RESERVE に取り込まれます（今日から120日先の診療日）。Air の予約はプログラムからは変えられません。
  • 新しく登録された患者は「要確認」に出ます。毎日、受付で確かめて印を外してください（設定 → リマインド → Airリザーブの取り込みの「要確認の患者」）。
  • プログラムがおかしな予約を入れ続けるときは、まず「このキーを無効化」で止めてください。入った予約は変更履歴で探せます。
  • 接続キーは、使わなくなったら無効化してください。最終利用の日時が設定画面に出ます。

9. 一覧表と、プログラムに貼るスキーマ（技術者向け）

入口：https://reserve.ishidahihuka.jp/api/v1/integration/booking。すべての要求にヘッダー X-Booking-Token: （接続キー）（または Authorization: Bearer （接続キー））を付けます。本文は JSON（Content-Type: application/json）。日時は ISO 8601（+09:00 付き）、日付は YYYY-MM-DD。

操作方法とパス内容
pingGET /ping接続の確認
getOptionsGET /options院の情報・レーン・メニュー
getDayGET /day?date=YYYY-MM-DDその日の予約（取り消し済みを含む）
findPatientsGET /patients?q=…氏名・フリガナ・電話・診察券番号・予約申請IDで探す（最大10人）
ensurePatientPOST /patients探して、いなければ登録 {name, kana, birthDate?, phone?, email?}
createReservationPOST /reservations予約を入れる
getReservationGET /reservations/{id}予約を1件読む
updateReservationPATCH /reservations/{id}日時・レーン・メニュー・メモ・予約申請ID・状態（予約／キャンセル／無断キャンセル）を変える（version 必須）
createMenuPOST /menusメニューを作る {name, duration, defaultMinutes?, priceYen?, abbr?}
cancelReservationPOST /reservations/{id}/cancel取り消す（version 必須。DELETE /reservations/{id} でも同じ）

例（curl）

KEY='bk_…'   # 接続キー（画面からコピーしたもの）
API='https://reserve.ishidahihuka.jp/api/v1/integration/booking'
curl -s "$API/options" -H "X-Booking-Token: $KEY"
curl -s "$API/day?date=2026-10-21" -H "X-Booking-Token: $KEY"
curl -s -X POST "$API/reservations" -H "X-Booking-Token: $KEY" -H 'Content-Type: application/json' \
  -d '{"patientId":"p-new-…","laneId":"l1","menuIds":["m3"],"startAt":"2026-10-21T10:00:00+09:00","endAt":"2026-10-21T10:30:00+09:00"}'

10. スタッフの画面と同じ操作（カルテ・写真・問診票・同意書・見積・設定）

入口：https://reserve.ishidahihuka.jp/api/v1/integration/booking/api のあとに、スタッフの画面が使っているパスを続けます。接続キー（X-Booking-Token）は予約の入口と同じです。院長と同じ権限で動き、変更履歴・操作ログには「自動予約（キーの名前）」と残ります。

  • 変える前に、必ず GET で今の内容を読み、返ってきた version を付けて送ります（ほかの人が先に直していると 409 になります。読み直してやり直してください）。
  • 送る形は、GET で読んだ形に合わせます。知らない項目を送ると「入力内容が正しくありません」（400）になります。
  • この入口では、予約の入口のような二重予約・Air の予約の確認はしません。予約の操作は、なるべく予約の入口（4〜6章）を使ってください。
扱うもの方法とパス（入口のあとに続ける）内容
その日の予定GET /day?date=YYYY-MM-DD予約・患者・レーン・メニュー（画面のカレンダーと同じ）
受付メモ・TodaysメモPUT /reception-notes/{日付}/{患者}、/day-notes/…日付ごとのメモ
患者を探す・登録GET /patients?q=…、POST /patients
患者の全部GET /patients/{id}基本情報・施術歴・日付ごとのメモ・今後の予約
基本情報を直すPATCH /patients/{id}version と直す項目（電話・住所・既往歴・内服・アレルギー・メモ など）
日付ごとのメモ（施術歴）PUT /patients/{id}/visits/{日付}その日の記録
カルテ（施術の記録）GET・POST /patients/{id}/charts、PATCH /charts/{id}、POST /charts/{id}/delete部位・条件・所見など
写真・ファイルGET /patients/{id}/files、GET /files/{id}、POST /patients/{id}/files一覧・中身・追加
問診票GET /patients/{id}/questionnaires、GET /questionnaires/list?from=&to=&q=、GET /questionnaires/{id}回答の全文
同意書GET・POST /patients/{id}/consents、/consents/{id}、GET /consent-templates署名済みの同意書・ひな形
見積GET・POST /patients/{id}/estimates、GET・PATCH /estimates/{id}
設定GET /settings、PATCH /clinic、/lanes・/menus・/stages・/products・/prices、GET・PUT /admin/reminders、GET・PUT /admin/air-sync、GET・POST /monshin/form院の情報・レーン・メニュー・状態・スキンケア・料金表・リマインド・Air 取り込み・問診票の質問
記録GET /audit、GET /access-log?from=&to=変更履歴・閲覧の記録
