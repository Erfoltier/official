# 予約カレンダー（美容皮膚科向け・試作）

美容皮膚科の受付・看護師・医師が、1日の予約を1画面で読めるようにする予約管理Webアプリの試作です。
企画書の「第0段階：カレンダー部分の試作」にあたります。

> **注意**：試作版です。データはサーバー上のファイル（SQLite、暗号化）に保存され、再起動しても消えません。
> 開発時に入っている患者・予約はすべて架空のダミーデータです。本番の認証（パスキー等）と外部の脆弱性診断が済むまで、**実際の患者情報を入力しないでください。**
> レーンとメニューは、Airリザーブ（いしだ皮フ科）の設定を 2026-10-05 に読み取って移したものです（`src/lib/seed/airreserve-import.ts`）。

## できること

| 機能 | 内容 |
| --- | --- |
| 短い枠も読める | 枠の高さに応じて「複数行」「1行（患者名｜施術略称）」「小さい1行」と表示を切り替える。5分枠でも最低15pxの高さを確保し、重なる場合は横に並べる |
| 時間軸の拡大・縮小 | スマホ・タブレットは2本指のピンチ、PCはCtrl＋ホイール（トラックパッドのピンチ）、ツールバーの −／＋／スライダー。指の下の時刻を固定したまま拡大する |
| 1日全体表示 | 「全体」で診療時間（初期値 9:30〜19:00）全体を画面に収める。「今」で現在時刻へ移動 |
| 予約の移動・長さ変更 | ドラッグで時間・レーンを変更、下端のつまみで長さを変更（5分刻み）。タッチは長押し、または選択中の予約をそのままドラッグ |
| 予約の登録 | 空いている枠をクリック／タップ → 患者検索・メニュー（複数可、絞り込み検索あり）・時間を選んで登録。メニューの提供時間の範囲外や、通常そのレーンで行わないメニューは警告を出す |
| 患者の登録 | 予約登録の画面から新しい患者を登録。**氏名は漢字・ひらがな・カタカナ・ローマ字を混ぜて入力できる**（例：山田 Anna、さくら 田中、LEE Min-ji）。フリガナと別の表記（ローマ字・旧姓など）も持てる |
| 患者情報の編集 | 患者一覧（👤）から検索して開くか、予約の詳細パネルの「患者情報を見る・編集する」から開く。氏名・フリガナ・別の表記・診察券番号・生年月日（年齢表示）・電話・メール・注意事項・院内メモを編集でき、変更した項目は色が付く。予約履歴（今後／これまで）とLINEの紐付け状態も表示し、紐付けの解除ができる |
| 同時編集の保護 | 2台で同じ患者を編集した場合、後から保存した側を止めて最新の読み込みを促す（上書きしない） |
| 変更履歴 | 患者情報を「いつ・誰が・どの項目を」変えたかを記録して表示する。値そのもの（個人情報）は履歴に残さない |
| 施術歴・簡易カルテ | 患者画面の最初に、日付ごとの施術内容・自由記載のメモ・その時点で使っているスキンケアを表で表示。行ごとにその場で記入でき、予約のない日の記録も追加できる。スキンケアは候補から選ぶか自由入力、「前回と同じ内容」も入れられる。その下に今後の予約の表 |
| 患者の検索 | 氏名・フリガナ・別の表記・診察券番号・電話番号で検索。ひらがな／カタカナ、全角／半角、大文字／小文字、空白の違いは無視する |
| レーンの設定 | 設定画面（⚙）でレーンの追加・名前変更・並べ替え・表示／非表示・削除。表示できるのは1〜30本。今日以降の予約が残るレーンは非表示にできず、予約の記録が一度もないレーンだけ削除できる |
| 患者の削除 | 診療の記録は保存が必要なため、消さずに「削除済み」にして検索・一覧から外す（理由・日時・操作者を記録、復元可）。今日以降の予約がある患者は削除できない。院長・管理者と受付のみ |
| 重複患者の統合 | 氏名・フリガナ・電話番号が同じ患者を「重複の可能性」として患者画面に表示。残す方を選ぶと、予約と施術歴を移し、空欄を補い、注意事項・メモをつなげる（同じ日の記録はつなげる）。事前に何が移るかを確認してから実行。まとめた側は削除扱いで残り、統合先へのリンクが出る。院長・管理者と受付のみ |
| メニューの設定 | 設定画面でメニューの追加・編集・並べ替え。提供時間（固定／最小〜最大と刻み）、予約時の初期値、開始時間の刻み、料金、同時予約数、行えるレーン、略称、色 |
| 状態の管理 | 予約 → 来院 → 施術中 → 会計待ち → 完了、キャンセル、無断キャンセル。枠の色・線で区別 |
| 現場向けの配慮 | 現在時刻の線、注意事項ありの印（!）、LINE紐付け済みの印、同じレーンで時間が重なる予約の印（右上の赤い三角） |
| 氏名を伏せる | 患者から画面が見える場所向けに、姓の1文字以外を伏せる |
| 端末別の表示 | PCは詳細パネルを右に、スマホは下から表示。レーンの絞り込み（1レーン表示）に対応 |
| データの保存 | 予約・患者・施術メモ・設定・スタッフ・操作ログをファイル（SQLite）に保存。再起動しても消えない。1件ずつAES-256-GCMで暗号化し、ファイルとフォルダはサーバー本人だけが読める権限にする。複数件をまとめて変える操作（統合・並べ替え等）は、途中で失敗したら全部取り消す |
| 他端末の変更の反映 | 20秒ごと、および画面に戻ったときに再読み込み。同時編集は版番号で検出し、後から保存した側に知らせる |

## 起動方法

```bash
cd apps/reserve
npm install
npm run dev          # http://localhost:3000
npm test             # ロジックの単体テスト
npm run typecheck
npm run lint
```

特定の日を開く：`http://localhost:3000/?date=2026-10-07`

## 環境変数

`.env.example` を `.env.local` にコピーして設定します（`.env*` はGitに含めません）。

| 変数 | 用途 |
| --- | --- |
| `STAFF_BASIC_AUTH` | `ユーザー名:パスワード`。設定すると画面とAPIにBasic認証がかかる。**本番ビルドで未設定だと全リクエストを拒否（503）する** |
| `SESSION_SECRET` | スタッフのログイン状態（Cookie）の署名用（32文字以上）。**本番で未設定だとログインできない**。開発時は起動ごとに自動で作る |
| `DATA_ENCRYPTION_KEY` | 保存データの暗号鍵（64桁の16進数、`openssl rand -hex 32` で作る）。**本番では必須**。開発時は `.data/dev.key` を自動で作る。**鍵を失うとデータは読めなくなる**ので、サーバーとは別の安全な場所にも控える |
| `INITIAL_ADMIN_PIN` | 本番の初回起動時に作る「院長」アカウントのPIN（4〜8桁）。スタッフが1人もいないときだけ使う |
| `RESERVE_DATA_DIR` / `RESERVE_DB` | 保存先のフォルダ（既定 `./.data`）／データベースファイルの直接指定 |
| `RESERVE_DEMO` | `1` で架空の患者・予約を入れる、`0` で入れない。未設定なら開発時は入れ、本番では入れない |
| `INTEGRATION_API_TOKEN` | 外部連携API用のトークン（32文字以上）。未設定なら外部連携APIは停止（503） |

## データの保存とバックアップ

- 保存先：`.data/reserve.db`（Gitには含めない）。中身は1件ずつ暗号化されている
- 初回起動時に、Airリザーブから移したレーン・メニューを入れる。開発時はデモの患者・予約も入れる
- 開発中にデモデータを作り直したいときは、サーバーを止めて `.data/` を消す（**本番では絶対にしない**）
- バックアップ：`npm run backup` で `.data/backups/` に日時付きのコピーを作る（直近30個を残す）。
  `BACKUP_DIR=/別のディスク npm run backup` のように、サーバーとは別の場所に保存するのがおすすめ。毎日決まった時刻に実行する設定（cron 等）を推奨
- 復元：サーバーを止め、`reserve.db`（と `-wal` `-shm`）をバックアップのファイルで置き換えて起動する。同じ暗号鍵が必要
- 注意：Node.js 標準の SQLite（試験的な機能）を使っており、サーバー1台での運用が前提。複数院・複数台で動かす段階で PostgreSQL に移す（保存の形は同じなので移しやすい作り）

アクセスは2段階です。

1. **院の入口**：Basic認証（`STAFF_BASIC_AUTH`）
2. **スタッフのログイン**：名前を選んでPIN（4〜8桁）を入力。初期スタッフ5名（院長・医師・看護師2名・受付）のPINは試作用にすべて `1234`。設定 → スタッフ（院長・管理者のみ）で追加・役割変更・利用停止・PIN変更ができる

スタッフのログインについて：
- PINは scrypt でハッシュ化して保存し、5回続けて間違えると5分間ロックする
- ログイン状態は署名付きCookie（HttpOnly・SameSite=Strict、本番はSecure）で12時間有効。PIN変更・利用停止・役割変更で即座に無効になる
- 予約・患者情報・施術メモ・設定の変更には、操作したスタッフが記録される。患者画面の変更履歴、施術メモの「記入：」、予約詳細の「担当記録」で確認でき、院長・管理者は設定 → 操作ログで全体を見られる（患者情報の値は操作ログに残さない）
- 役割による制限：スタッフ管理・操作ログは院長・管理者のみ、レーン・メニューの変更は院長・管理者と受付のみ

本番では、パスキー（指紋・顔認証）と端末登録に置き換える予定です。

## 外部連携API（前日リマインド等）

LINEなどの送信は後から外部プログラムで行う前提で、前日に予約を拾える口だけ用意しています。

### 指定日の予約一覧

```
GET /api/v1/integration/reminders?date=2026-10-07
Authorization: Bearer <INTEGRATION_API_TOKEN>
```

```json
{
  "schemaVersion": 1,
  "date": "2026-10-07",
  "clinicName": "デモ皮フ科",
  "generatedAt": "2026-10-06T09:00:00.000Z",
  "items": [
    {
      "reservationId": "r-2026-10-07-39",
      "version": 1,
      "startAt": "2026-10-07T09:30:00+09:00",
      "endAt": "2026-10-07T10:30:00+09:00",
      "laneName": "1番レーン(レーザー脱毛など)",
      "menuNames": ["レーザー脱毛"],
      "patient": { "id": "p-0028", "name": "田中 芽依", "lineUserId": "U…", "phone": "…", "email": null },
      "reminderStatus": "pending"
    }
  ]
}
```

- キャンセル・無断キャンセルは含まれません
- 1予約＝1件です。同じ患者が1日に複数予約している場合は、送信側で患者IDごとにまとめてください
- `lineUserId` は患者本人がQRコードで紐付けを済ませた場合だけ入ります（`null` なら送らない）
- 日時は常に日本時間のISO 8601形式です

### 送信結果の書き戻し

```
POST /api/v1/integration/reminders/{reservationId}
Authorization: Bearer <INTEGRATION_API_TOKEN>
Content-Type: application/json

{"status": "sent"}      // sent | skipped | failed
```

予約の時刻が変更されると、リマインドの状態は自動で `pending`（未送信）に戻ります。

## セキュリティ上の配慮（試作段階）

- 本番ビルドは認証設定がないと起動しても応答しない（誤公開防止）
- Content-Security-Policy で外部スクリプト・外部通信・埋め込みを禁止、検索エンジンにも登録させない
- APIの応答はキャッシュさせない。エラー時に患者情報を応答やログに出さない
- 入力はすべてサーバー側で検証（zod）。日をまたぐ予約や不正な時刻は拒否
- 端末に保存するのは表示設定（拡大率など）だけで、患者情報は保存しない
- 外部連携トークンの比較は時間差の出ない方法で行う

## まだやっていないこと

- PostgreSQL（院ごとの行分離）への移行。今は1台のサーバーのファイルに保存
- 本番の認証・権限・操作の監査ログ
- 週表示、診療時間・休診日の設定画面
- メニューの「開始時間の刻み」「同時予約数」は保存のみで、予約登録時の制限にはまだ使っていない
- LINE連携（紐付け・チャット・リマインド送信）
- Airリザーブからのデータ取り込み
