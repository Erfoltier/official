# 予約カレンダー PHP版（ロリポップ等の共用サーバー用）

画面は静的ファイル、裏側の処理（API）は PHP で動く版です。
Node.js 版と同じAPI・同じ保存形式なので、データはそのまま行き来できます。

> **テスト用です。** ロリポップ等の共用サーバーは、医療情報のガイドライン（3省2ガイドライン）を前提にしたサーバーではありません。
> **実在の患者情報は入れないでください。** 同梱のデモデータ（架空の患者・予約）で操作を確かめる用途に使います。

## 必要なもの

- ロリポップ！ ハイスピードプラン（他の PHP 共用サーバーでも可）
- PHP 8.1 以上（8.3 推奨）。SQLite（pdo_sqlite）と OpenSSL が使えること

## 置き方

1. `reserve-lolipop.zip` を展開すると `reserve` フォルダができます。
2. **ロリポップ！FTP**（ユーザー専用ページ → サーバーの管理・設定 → ロリポップ！FTP）か FTP ソフトで、
   ホームページの公開フォルダの中に `reserve` フォルダごとアップロードします。
   - 既存のホームページや LINE 予約フォームのファイルには触れません（別フォルダに置くだけです）。
3. PHP のバージョンを確認します（ユーザー専用ページ → サーバーの管理・設定 → PHP設定）。
   - 8.1 以上ならそのままで構いません。
   - それより古い場合は、同じドメインの LINE 予約フォームに影響することがあるため、変更前にご相談ください。
4. ブラウザで `https://（ドメイン）/reserve/api/v1/health` を開き、`{"ok":true}` と出れば動いています。

## 入口の鍵（Basic認証）を掛ける

院のスタッフ以外が画面を開けないよう、フォルダに ID・パスワードを掛けます。

1. ユーザー専用ページ → セキュリティ → **アクセス制限** で、`reserve` フォルダを選び、ID とパスワードを設定します。
2. 設定後、ロリポップ！FTP で `reserve/.htaccess` を開きます。`RewriteRule ^api/v1/ api/index.php` の行が残っていることを確認してください。
   - もし消えていたら、ZIP の中の `.htaccess` の内容を末尾に貼り付けて保存します。

## 使い方

- `https://（ドメイン）/reserve/` を開く → Basic認証の ID・パスワード → スタッフを選んで PIN を入力
- デモ版の PIN は全員 `1234` です（設定 → スタッフ で変更できます）

## 保存時にエラー（403 など）が出るとき

ロリポップの **WAF**（不正アクセス防御）が、メモなどの入力内容を攻撃と誤判定することがあります。

- ユーザー専用ページ → セキュリティ → WAF の「ログ」で、該当のアクセスが記録されていないか確認してください。
- 記録されている場合は、テスト期間中だけそのドメインの WAF を無効にするか、ご相談ください。

## バックアップ

ロリポップ！FTP で、次の **2つを両方** ダウンロードして保管します。

- `reserve/data/reserve.db`（データ本体。中身は暗号化されています）
- `reserve/config.php`（暗号鍵。**これがないとデータは読めません**）

## 新しい版に入れ替えるとき

`reserve/data/` フォルダと `reserve/config.php` は **上書きしない** でください。それ以外のファイルを入れ替えます。

## 外部連携（前日リマインド用の予約一覧）

送信プログラム（Codex で作成中のもの）からは、次のように取得します。

```
GET https://（ドメイン）/reserve/api/v1/integration/reminders?date=2026-10-07
X-Integration-Token: （config.php の integration_token の値）
Authorization: Basic （アクセス制限の ID:パスワード）
```

送信結果は次のように書き戻します。

```
POST https://（ドメイン）/reserve/api/v1/integration/reminders/（予約ID）
{"status": "sent"}       ← "sent" / "skipped" / "failed"
```

### 自動入力（予約申請ID・M3カルテ番号）

LINE予約フォームや M3 側のプログラムから、次のように書き込めます（同じく連携トークンと Basic認証が必要）。

```
POST https://（ドメイン）/reserve/api/v1/integration/reservations/（予約ID）/request-id
{"requestId": "R2026100506574020A34A8B"}

POST https://（ドメイン）/reserve/api/v1/integration/patients/（患者ID）/m3-chart-no
{"m3ChartNo": "004567"}
```

予約ID・患者IDは、上の予約一覧（`reservationId`、`patient.id`）で分かります。書き込みは変更履歴に「外部連携」として残ります。

## 写真・同意書などのファイル

予約の詳細の「📷 撮影」「📎 ファイル」から追加します（ドラッグ＆ドロップも可）。写真・PDF・Word、1ファイル10MBまで。
写真は自動で縮小してから送ります。中身は暗号化して `data/reserve.db` に保存されるので、バックアップはこれまでどおり
`data/reserve.db` と `config.php` の2つです。

## 見積書

予約の詳細の「📝 見積書」か、患者画面の「見積書」から作ります。メニュー・スキンケア＆内服を押して追加し、値段と数量を直して保存すると、
見積番号（年ごとの通し番号）がつき、A4の見積書を印刷できます（印刷画面で「PDFに保存」も可）。
住所・電話・発行者・有効期限・注意書きは「設定 → 院の情報・診療時間」で変えられます。

## 料金表（見積書の候補）

「設定 → 料金表」に、見積書で選べる料金が並びます。

- **ホームページが正本**です。料金表ページと脱毛ページを1日1回自動で取り込み直します（設定画面の「今すぐ取り込む」でもすぐ取り込めます）。
  脱毛ページのように「税抜」と書かれた表は、税込（×1.1、1円未満切り捨て）に直します。
  ページが読めなかったときは、前回の内容のまま使います。
- **スプレッドシート（自費商品、メニュー外値段表）**からは、シートに入れた自動処理（Apps Script）が値段を送ってきます。
  入れ方は `integrations/sheet-prices.gs` の先頭に書いてあります（スクリプト プロパティに送り先・連携トークン・アクセス制限の ID とパスワードを入れ、`setup` を1回実行）。
  スタッフ用シートと旧価格の列は送りません。シートは公開しません。
- どちらにもない料金は「自由入力」で足せます。見積書でも、項目名・値段を自由に入れた行を作れます。

見積書は、印刷画面で「御見積書／御会計書」と「A4／A5」を切り替えられます。

## 同意書

予約の詳細の「📄 同意書」か、患者画面の「同意書」から作ります。同意書を選ぶと、患者名・生年月日・診察券番号・施術・同意日が入った本文が出ます。

- **この端末で署名する**：iPad などで指で署名し、署名入りの控えとして保存します（A4 で印刷・PDF にできます）。
- **署名せず印刷**：紙に署名してもらう用に印刷します。発行した記録は残ります。

ひな形は **Google ドライブの同意書フォルダの Google ドキュメントが正本**です。同意書を開く・発行するたびに、ドライブから**その時の最新の文面**を
読み込んで印刷します（ドライブで直せば次から反映。発行済みの控えは発行時の文面のまま残ります）。
`integrations/consent-templates.gs` を Apps Script に入れて「ウェブアプリ」としてデプロイし、その URL と合言葉を「設定 → 同意書 → 読み込み元」に入れます
（手順はファイルの先頭）。ドライブにつながらないときは、前回読み込んだ文面を使い、画面にそう表示します。
患者の情報は Google に送りません。Word・PDF の同意書は Google ドキュメントに変換して置いてください。
「設定 → 同意書」で、同意書ごとにメニューを選んでおくと、そのメニューの予約で先頭に出ます。

## カルテ（施術記録）

カレンダー右の予約の詳細、または患者画面の施術歴の日付にある「🩺 カルテ」から書きます。
施術名・部位・条件（機器・出力・ショット数など）・薬剤とロット番号・麻酔・所見と経過・次回の予定・施術者を、施術1件ごとに残します。
写真はその日のファイル（撮影・ファイル）がそのまま一緒に出ます。書く・直すはスタッフ全員、削除は書いた本人か管理操作のできるスタッフだけで、誰がいつ書いた・直したかが残ります。

## ファイルの構成

| パス | 中身 |
|---|---|
| `index.html`, `_next/` など | 画面（静的ファイル） |
| `api/index.php` | API の入口（`.htaccess` で `/reserve/api/v1/...` をここに集める） |
| `lib/` | 処理の本体（外からは開けない） |
| `data/` | データ（SQLite。外からは開けない） |
| `seed/seed.json` | 初回に入れるレーン・メニュー（Airリザーブから移した設定） |
| `config.php` | 暗号鍵・署名用の秘密の値・連携トークン（外からは開けない） |

## 開発者向け

- 一式の作成：`npm run build:lolipop` → `dist/reserve-lolipop.zip`
  - 暗号鍵などは毎回新しく作ります。`dist/` は Git に入れません。
  - `DEMO=0` で作ると、デモデータを入れずに院長アカウントの初期 PIN だけを作ります。
- Node.js 版と PHP 版の一致の確認：同じデータベースに同じ 178 手順の操作を行い、応答が一致することを確認済みです。
  対象はログイン、予約、患者、統合、レーン、メニュー、状態、スキンケア、ファイル、見積書、設定の復元、スタッフ、外部連携、ロックです。
