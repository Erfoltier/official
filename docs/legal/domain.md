## 2. 空いているかの確かめ方

1. JPRS WHOIS（https://whois.jprs.jp/）で `lanereserve.jp` などを検索します。「該当するデータがありません」と出たら空いています。
2. .com は、登録業者（お名前.com、さくらインターネット、Xserverドメイン など）の検索画面で確かめます。
3. 空いていても、**似た名前の商標がある場合は使わないほうが安全**です（trademark.md の調査とあわせて判断します）。
4. 他人の商標と同じドメインを、悪い目的で取ることは「不正競争防止法 第2条第1項第19号」で禁止されています。逆に、こちらの名前を他社に取られないよう、早めに取るのが一般的です。

> 注：この作業環境からは WHOIS に接続できないため、空いているかはまだ確かめていません。

### 追記：ムームードメイン・AWS で取る場合（2026-10-14）
- **ムームードメイン**：.jp・.com とも取れます。いしだ皮フ科のドメインと同じ業者で、管理に慣れている利点があります。更新料は Xserverドメインより年 1,000円前後高い見込みです。
  - **いしだ皮フ科（医療法人）のアカウントとは分け、当社名義の別アカウントで取ります。** 医療法人の契約や特典（ロリポップの無料ドメインなど）を当社のドメインに使うと、医療法人の財産を当社のために使った形になり、関係事業者との取引の整理（conflict-of-interest.md）と食い違います。
- **AWS（Route 53）**：AWS は、サーバーを借りてもドメインが無料になる特典はありません。.com は年 15 米ドル前後（2026年7月の価格改定後の第三者の集計）です。.jp も取れますが、国内の業者より割高な傾向があるので、公式の料金表（PDF）で確かめます。
- **決定案（2026-10-14）**：ムームードメインのアカウントは、医療法人ではなく理事長の個人名義（法人化の前に作ったもの）。このアカウントで取ってよい。条件は次の3つ。
  1. ドメインの**登録者（持ち主として登録する名前）は株式会社エアフォルティアコンサルティング**にする。
  2. **費用は当社が負担する**（個人のカードで払ったら、当社が立替金として精算する）。サーバーの特典の無料枠は使わない。
  3. 当社の取締役決定書に、このドメインは当社のもので、管理を株主個人のアカウントに預けていると記録する。
- 別の論点：いしだ皮フ科のドメイン（ishidahihuka.jp）とサーバーの契約も個人名義のまま、医療法人が使っている可能性がある。費用をどちらが払っているかを確かめ、医療法人の名義に移すか、使わせる約束を書面にしておくとよい。
- **DNS（ドメインの住所録）は、ドメインをどこで取っても AWS などへ向けられます。** 将来 AWS へ移る場合も、ドメインはムームーのままで構いません。

## 4. 取る順番

1. J-PlatPat で、明らかに似た商標がないかを先に確かめます（trademark.md 2章）。
2. 問題がなければ、**すぐに lanereserve.jp と lanereserve.com を取ります**。安く、取られると取り返すのが難しいためです。
3. 続けて商標を出願します。
4. 取ったら、次の設定をします。
   - 自動更新をオンにする（うっかり失効するのを防ぐため）
   - 業者の管理画面のログインに2段階認証を設定する
   - 登録者情報は会社名義にし、連絡先は会社の代表アドレスにする
   - 業者が勝手に別の業者へ移すのを防ぐ鍵（移管ロック）をかける

**支払いを伴うため、取る作業はユーザーの承認を得てから行います。**

## 5. いまの ishidahihuka.jp/reserve から移すときの段取り

### 5-1. 院ごとのURLの形（案）
| 形 | 例 | 判断 |
|---|---|---|
| **サブドメイン（おすすめ）** | `ishida.lanereserve.jp` | ◎ 院ごとにログイン情報（クッキー）や保存データが分かれ、混ざりません。「院ごとに分けて立ち上げる」形（saas-plan.md の C）と合います |
| パス | `lanereserve.jp/ishida/` | △ 同じ場所に全院が並ぶため、ログイン情報の分け方に注意が要ります |

- 紹介サイトは `lanereserve.jp`、管理用の画面は `admin.lanereserve.jp` など、役割ごとに分けます。
- 院の名前がURLに出ると困る場合は、番号の形（`c0123.lanereserve.jp`）も選べます。

### 5-2. SSL（通信の暗号化の証明書）
- 院ごとに証明書を取るか、`*.lanereserve.jp` のように全サブドメインをまとめて使える証明書（ワイルドカード証明書）を使います。
- 無料の Let's Encrypt でワイルドカード証明書を取るには、DNS（ドメインの住所録）を使った確認が必要です。DNS を自動で書き換えられる業者を選びます。
- 古い暗号方式を止める設定や、HTTPS だけで通信させる設定（HSTS）を入れます。

### 5-3. 移す手順（いしだ皮フ科の場合）
| 順 | やること | 注意 |
|---|---|---|
| 1 | 移す先の環境（サーバー）を用意する | saas-plan.md 第1章 |
| 2 | DNS の設定の持ち時間（TTL）を短くしておく | 切り替えのときに早く反映されるようにするため |
| 3 | 新しい環境でテスト用データを使って動作を確かめる | 本物の患者データでは試しません |
| 4 | 外部とのつながりの宛先を書き出す（下の表） | 漏れがあると予約の取り込みやリマインドが止まります |
| 5 | **院長の承認を得て**、休診日などにデータを移す | saas-plan.md 4-1 と同じく、本番データを移す前には承認が必要です |
| 6 | 外部サービスの宛先を、新しいURLに切り替える | |
| 7 | 古いURL（ishidahihuka.jp/reserve/）から新しいURLへ自動で転送する（301 転送） | ブックマークや、ホーム画面に置いたアプリからの入口を残すためです |
| 8 | しばらく古い環境を読み取り専用で残し、そのあと手順を決めて消す | データの消し方は記録に残します |

### 5-4. 切り替えが必要な外部の宛先
| つながり | 切り替えるもの |
|---|---|
| LINE 公式アカウント | Messaging API の Webhook URL（LINE からの通知の受け取り先）、LIFF（LINE の中で開く画面）の URL、リマインドの文中のリンク |
| Airリザーブ | 取り込みの仕組みが参照している URL や、取り込み用のファイルの置き場所 |
| Google フォーム | 問診票の送り先（Apps Script など）の URL |
| ネオボワール | 写真を取り込むときの送り先・置き場所 |
| 院のパソコン・タブレット | ブックマーク、ホーム画面のアイコン。スタッフは新しいURLで**ログインし直し**が必要です（ログイン情報はURLごとに別のため） |
| 入口の Basic 認証 | 新しい環境に設定し直します（パスワードはこの文書には書きません） |

### 5-5. メールを送る場合
- `lanereserve.jp` からメールを送るなら、送り元が本物だと証明する設定（SPF・DKIM・DMARC）を入れます。入れないと迷惑メール扱いになりやすいです。
